# Entity Diagrams / UML

## Zivybb — Local Music Player Application

This document defines the core data entities for Version 1 and their relationships, along with a high-level class view of the main domain objects. Diagrams use [Mermaid](https://mermaid.js.org/) syntax, which renders natively on GitHub.

## 1. Entity-Relationship Diagram

```mermaid

    SONG ||--o{ PLAYLIST_SONG : "appears in"
    PLAYLIST ||--o{ PLAYLIST_SONG : contains
    SONG }o--|| MOOD_TAG : "tagged with"
    SONG ||--o{ MISSING_FILE_RECORD : "may have"
    SETTINGS ||--|| EQUALIZER_PRESET : "current preset"
    BACKUP ||--o{ PLAYLIST : snapshots
    BACKUP ||--o{ SONG : "snapshots liked/tagged state"

    SONG {
        string id PK

        string title

        string album
        int durationMs

    }

    PLAYLIST {
        string id PK

        string sourceMoodTagId FK "nullable"

    }

    PLAYLIST_SONG {
        string playlistId FK
        string songId FK

    }

    MOOD_TAG {
        string id PK
        string label
        string colorHex
    }

    MISSING_FILE_RECORD {
        string id PK
        string songId FK

        datetime detectedAt
        string status "missing | relinked | removed"
    }

    EQUALIZER_PRESET {
        string id PK

    }

        string id PK

    }

    BACKUP {
        string id PK

    }
```

## 2. Domain Class Overview

```mermaid
classDiagram
    class Song {
        +String id
        +String filePath
        +String title
        +String artist
        +String album
        +Duration duration
        +MoodTag? moodTag
        +bool isLiked
        +bool isMissing
        +markMissing()
        +relink(String newPath)
    }

    class Playlist {
        +String id
        +String name
        +bool isAutoGenerated
        +List~Song~ songs
        +addSong(Song song)
        +removeSong(Song song)
        +reorder(int from, int to)
    }

    class MoodTag {
        +String id
        +String label
        +Color color
    }

    class EqualizerPreset {
        +String id
        +String name
        +List~double~ bandLevels
    }

    class Settings {
        +String themeId
        +Color visualizerColor
        +bool adaptiveDarkModeEnabled
        +EqualizerPreset currentPreset
    }

    class BackupManager {
        +createBackup() Backup
        +restore(Backup backup)
        +listBackups() List~Backup~
    }

    class MissingFileService {
        +scanForMatches(Song song) String?
        +autoRelinkAll()
    }

    Playlist "1" --> "many" Song : contains
    Song "many" --> "0..1" MoodTag : tagged with
    Settings "1" --> "1" EqualizerPreset : uses
    BackupManager --> Playlist : snapshots
    BackupManager --> Song : snapshots liked/tag state
    MissingFileService --> Song : monitors
```

## 3. Auto-Generated Playlist Flow (Sequence)

```mermaid
sequenceDiagram
    participant U as User
    participant UI as Library Screen
    participant PS as Playlist Service
    participant DB as Local Storage

    U->>UI: Tags songs with mood/energy labels
    UI->>PS: notifyMoodTagsUpdated()
    PS->>DB: query songs grouped by MoodTag
    DB-->>PS: grouped song lists
    PS->>DB: upsert auto-generated Playlist per MoodTag
    PS-->>UI: refreshed playlist list
    UI-->>U: Auto-generated playlists appear
```

## 4. Missing File Detection Flow

```mermaid
sequenceDiagram
    participant App as App Startup / Background Task
    participant MFS as MissingFileService
    participant FS as Device File System
    participant DB as Local Storage

    App->>MFS: scan for missing files
    MFS->>DB: get songs where isMissing = true
    DB-->>MFS: list of missing songs
    loop for each missing song
        MFS->>FS: search by filename / metadata
        alt match found
            FS-->>MFS: candidate file path
            MFS->>DB: relink(song, newPath)
        else no match
            MFS->>DB: leave flagged as missing
        end
    end
```

## Notes

- `PLAYLIST_SONG` is the join entity supporting many-to-many between `PLAYLIST` and `SONG`, with an explicit `position` field to preserve manual ordering.
- Auto-generated playlists (`isAutoGenerated = true`) are derived from `MOOD_TAG` groupings and are regenerated rather than manually edited.
- `BACKUP` stores a serialized snapshot; the exact serialization format (JSON file, SQLite export, etc.) is an implementation decision to be finalized during Week 4 (Backup/Restore) of the development plan.
